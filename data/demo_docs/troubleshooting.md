# EchoMind-PM 项目管理方法手册

## WBS 工作分解结构

WBS 是把项目交付物和项目工作细分为更小、更易管理的组成部分的方法。

### 拆解原则
- 遵循 MECE：子任务相互独立、完全穷尽，不重叠不遗漏。
- 每个叶子节点任务要可执行、可验收、可分配。
- 拆解粒度到"一个负责人能在 3-5 天内完成"即可，不要过细。

### 典型层级
- 第一层：阶段（需求、设计、开发、测试、上线）
- 第二层：模块 / 工作包
- 第三层：具体任务（含负责人、工期、交付物）

## 里程碑管理

里程碑是项目中的关键时间节点，代表阶段性成果的验收点。

- 每个里程碑对应可演示/可验收的成果，例如"需求冻结""Beta 上线"。
- 里程碑之间应留有缓冲时间。
- 里程碑一旦确立，变更需要走变更审批流程。

## 任务状态口径

统一使用：未开始 / 进行中 / 已完成 / 已阻塞 / 已取消。

- 逾期判定：任务截止日期已过且状态不是"已完成"。
- 风险是"可能发生"，问题是"已经发生"，描述时要区分。

## 周报结构

推荐结构：本周完成 / 进行中 / 风险与阻塞 / 下周计划 / 需要协调事项。

- 数据要基于任务实际状态，可追溯到具体任务。
- 突出需要负责人或上级决策的事项。

## 关键路径法（CPM）

关键路径是项目中最长的依赖链，决定项目最短工期。

- 关键路径上的任何任务延期，都会直接推迟项目整体完成时间。
- 排期时优先保障关键路径任务，高风险任务建议加缓冲。
